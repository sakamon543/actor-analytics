効率化を理由に、指定ファイルの一部だけ読むことは禁止する。
このSKILL.md・参照ファイル・ナレッジ・素材すべて、作業開始前に全行Readすること。

以下の判断は全て禁止：
- 「要点だけ拾えばいい」
- 「前に読んだから大体覚えてる」
- 「長いから途中まででいい」

# 恋愛系AIポスト作成スキル

恋愛系演者運用の**全工程の統括スキル**。
note立ち上げ（記事作成）と Xポスト量産（短文SNS）の両方をカバーする。

起動したら**ユーザー確認は最小限、ノンストップで最後まで走る**。

---

## 起動モード（2択）

スキル発動直後、以下のどちらかを必ず判定する。曖昧な発言なら確認質問する。

### A. 新規立ち上げモード

**典型起動文**：
- 「{演者名}を立ち上げて」
- 「新演者{演者名}作って」
- 「恋愛系の新規アカウント立ち上げて」

**実行内容**：
- Phase 1（コンセプト設計）→ Phase 9（Xポスト量産）→ **Phase 10（自動改善ループ取り込み）** までノンストップ
- 完走後、3日後に最初のループサイクルが自動発火する状態になる

### B. 既存アカ取り込みモード（NEW）

**典型起動文**：
- 「{演者名}を改善ループに取り込んで」
- 「{演者名}のループ取り込み」
- 「{演者名}を自動改善に乗せて」

**実行内容**：
- すでに運用中／停止中のアカウントを自動改善ループに登録するだけ
- 既存のセールスレター・過去ポストから演者情報を抽出して `アカウント情報総合管理.md` を作成
- ループ用ファイル群を生成して GitHub に push → VPS が3日後に最初のサイクル発火
- 詳細手順は **`スキル/スキル_ループ取り込み.md`** を参照

### C. 追加商品量産モード（既存アカに商品を足す／作り直す・2026-07-03新設）

**典型起動文**：
- 「{演者名}に追加で商品作って。コンセプトは〇〇」
- 「{演者名}で商品もう1本」「{演者名}の商品3本追加」
- 「{演者名}の{商品名}、売れてないから作り直して」
- 「{演者名}の追加商品案出して」（コンセプト候補の提案だけ）

**思想（2026-07-06改訂）**：人間がやるのは**C-1で一気に済ませる4つ（①コンセプト選び ②価格 ③サムネ3案から1枚選ぶ ④noteログイン）＋最後にマガジン化の要否を答えるだけ**。それ以外は公開まで全自動（有料設定も公開もAI）。
リサーチ・アカウント設計は済んでる前提なので**Phase 1のフルコースを回さない**。詳細フローは下の「Phase C」参照。

**実行内容**：Phase C-1（商品コンセプトブロック作成）→ Phase 2〜8 を**商品別パス**で実行。Phase 9（新商品切り口のポスト）は指示があれば。

### D. 無料note作成モード（旧「恋愛系無料note作成」スキルを統合・2026-07-31）

**典型起動文**：「{演者名}の無料note作って」「無料記事書いて」

**実行内容**：集客用の無料note記事を作成する。実行手順とナレッジは以下を**両方全文Read**してから：
- 実行手順：ナレッジ直下 `スキル_無料note作成/SKILL.md`
- パターンナレッジ：ナレッジ直下 `スキル_無料note作成/ナレッジ_無料記事パターン.md`

完成後は**AI感監視員**（ナレッジ `.claude/skills/AI感監視員/`：SKILL.md＋AIっぽい文章表現大全.md）を必ず通す。読めない環境でも最低限3つの問いを全文に当てる：体験者の口か／現実より整いすぎてないか／同じ型の使い回しになってないか。単語・言い回しレベルだけ直し、構成は変えない。監視員を通していない記事は出さない。
※無料記事は必須装備（思考スキル_売上逆算.md：note内は教育が加速する・無料note経由のクリック率は有料誘導の10〜20倍）。

### モード判定の指針

- 「アカウント存在する／立ち上げ済み／過去に作った」＋ループ関連 → B
- 「新しく作る／立ち上げる／新演者」が明示 → A
- 「追加で商品／もう1本／作り直し／商品案」＋既存演者名 → C
- 「無料note／無料記事」 → D
- 「ポスト◯本作って」 → Phase 9 単体起動

**演者名やモードが読み取れない起動**（「恋愛系AIポスト作成を発動」「恋愛系スキル起動」だけ等）の場合は、以下のメニューを1回だけ提示して選ばせる：

```
どのモードでいきますか？
1. 新規演者の立ち上げ（コンセプト設計〜note公開準備〜ポストまでフル）
2. 既存アカに商品を追加（人間はネーミング・サムネ・公開だけ）
3. 売れてない商品の作り直し
4. ポスト量産（10本〜300本）
5. 既存アカを自動改善ループに取り込み
6. 無料note記事の作成
→ 番号＋演者名（＋商品コンセプトがあれば一言）をください
```

選択後はノンストップ（各モードの確認ポイント以外で止まらない）。

> 自動改善ループの仕組み・全体像は **`自動改善ループの仕組み.md`** を参照。
> 何が動いていて、ユーザーは何をすればいいか、すべて1ファイルにまとめてある。

## 設計思想（ユーザー確認は最小限）

過去の断続原因を全部このスキルで潰す：

| 過去の断続ポイント | このスキルでの対処 |
|---|---|
| letter保存忘れ | 各Phaseで Write必須、チャット出力のみで完了禁止 |
| 画像文字化け | 崩れた枚のみ再生成（直らなければ gemini-3-pro-image-preview に一時切替） |
| デザイン5択で毎回ユーザー選択待ち | 初回のみ提示、選んだら **アカウント設定に design_id 保存**、2回目以降は無確認 |
| 結合MD・スクリプト生成の手作業 | Phase 5で自動展開 |
| 監視員チェックで毎回ユーザー確認 | B以下を自動書き直し、ユーザー確認なし |
| サムネ商品名の改変 | **メイン=商品名そのまま固定**、3案バリエはラベル＋サブのみ |

ユーザー確認を入れるのは（モードC・2026-07-06改訂で前倒し集約）：
- **最初のワンストップ（C-1）**：「コンセプト選び／価格確定／サムネ3案から1枚選ぶ／noteログイン（reCAPTCHAはここで1回だけ通す）」をまとめて済ませる。人間タッチはここに集約
- **最後にマガジン化の要否だけ（Phase 11）**：全商品が公開まで終わった後、「マガジン化しますか？どの商品×どの商品を何円で」とだけ聞く（並列タブで他商品がまだ途中の可能性があるため、ここは人間トリガー）

**公開はもう聞かない**：C-1でコンセプト・価格・サムネまで全部決めてあるので、Phase 2〜8＋公開まで一切止まらず全自動（＝旧「公開して」の停止は廃止）。それ以外も止まらない。デザインID初回選択もAI自動選定（Phase 3.5参照・聞かない）。

### 【生成物の途中確認は禁止】（2026-07-06 阪本さん明言）

コンセプト確定後は、**letter・content・図解・声画像・サムネ文字案の出来をユーザーに見せて「これでいいですか」と承認待ちするのは禁止**。Phase 8の完了報告で全部まとめて見せる。

- 品質担保は**自動セルフチェックで行う**：競合4本分析／監視員チェック（B以下自動書き直し）／AI感チェック事例集照合／音読テスト／画像のRead目視（文字化け・英語混入・デザイン統一）。つまり「確認しない」＝「チェックしない」ではない。**チェックは全部AIが自分でやり、その結果だけPhase 8で報告する**
- 画像が崩れてたらユーザーに聞かずに自分で再生成する（エラー時リトライルール参照）
- 途中で判断に迷ったら、**既存商品・競合レター・各ルールファイルに答えを探す**。それでも決めきれない事項は仮決定して進み、Phase 8報告に「ここはこう判断した」と書く
- 止まっていいのは：ログインreCAPTCHA等の人間しか通せない壁／破壊的操作（公開・削除・課金）の直前、の2つだけ

## フェーズ構造

### Phase 1: コンセプト設計＋引き継ぎ書合体（阪本さん本人推奨）

**参照**: `スキル_恋愛コンセプト設計.md`

- アカウント設定_〇〇.md を作成（Step 1〜7）
- Step 8 の出力前チェックを通す
- Step 9 で引き継ぎ_〇〇.md を合体生成（生のまま、整形しない）

**出力（Write必須）**：
- `{アカウント名}/アカウント設定_{アカウント名}.md`
- `{アカウント名}/引き継ぎ_{アカウント名}.md`

阪本さんが自分でやる場合はこのフェーズだけ完走させて、フェーズ2以降は外注に渡してもOK。

### Phase C: 追加商品量産フロー（モードC専用・Phase 1の代わり）

**目的：既存アカに2本目以降の商品を、人間の作業＝コンセプト（ネーミング）とサムネと公開だけで量産する。**

> ## 【最重要・絶対の歯止め】1商品ずつ・工程飛ばし禁止・未完成公開禁止（2026-07-05 事故を受けて追加）
>
> **複数商品を一気に作ろうとすると必ず工程を飛ばして中身がゴミになる。1商品ずつ、全工程をちゃんと通し切ってから次に進む。速さより質。焦らない。**
>
> - **1商品ずつ**：モードCで「商品2〜3本作って」と言われても、**同時並行で走らせない**。C-1→Phase2→…→Phase8を1本完走（**途中でユーザーに承認を求めない。Phase 8で一括報告**）→阪本さんが中身を見てOK→次の1本。1本のクオリティが担保できるまで次に着手しない
> - **工程飛ばし全面禁止**：Phase 2の競合レター4本分析（Step2-0）／AI感チェック事例集との照合／監視員チェック（B以下書き直し）／Phase 4の画像13枚／Phase 4.5の声画像／Phase 7のサムネ文字案、**どれ1つも飛ばさない**。「全部自動・止まるな」は「**確認で止まるな**」であって「**工程を省いて速く出せ**」では断じてない。逆も同じで、「工程を全部通せ」は「**各工程でユーザーに見せて止まれ**」ではない（設計思想の【生成物の途中確認は禁止】参照）
> - **未完成で公開しない（自動公開でも品質ゲートは絶対）**：公開は自動化したが、本編が基準字数（17,000〜20,000字）に届いてない／画像14枚が揃ってない（保存検証NG）／サムネ未選択／監視員チェック未通過、のどれか1つでもあれば**自動公開を止めて下書きで待機し、Phase 8で「ここが未達なので公開保留」と報告**。中途半端を本番アカに自動で上げるのだけは絶対にしない
> - **丸記号禁止**：①②③・〇●・■ 等の記号列挙はAI感の代表。本文は普通の文章で書く（口調文体ルール_一般人感.md／memory: feedback_no_ai_style_writing）
> - **既存商品が品質バー**：その演者の既存noteが基準。字数・章立て・実例密度・声が既存に並ばないものは未完成扱い

#### C-0（任意）：商品案の提案（「商品案出して」と言われた時だけ）

既存の `アカウント設定_{アカウント名}.md`＋`letter.md`＋`knowledge/target_research.md`＋競合レター集＋`商品コンセプト台帳.md` を読み、**追加商品案を3〜5個提案**する。各案＝切り口（どの常識にどう切り込むか）／仮ネーミング（手法名）／価格帯（アカ内構成での位置：メイン/サブ/ミニ）。**台帳に「売れてる切り口」があればそれの流用案を必ず含める**（実証済み＞新案。被りは気にしない）。
- 各案は `スキル_恋愛コンセプト設計.md` Step 4 の**売れるコンセプト検査（5問）**を通してから出す（売れないコンセプトを並べない）
- 人間が選んでネーミング確定 → C-1へ

#### C-1：商品コンセプトブロック作成（フルのPhase 1はやらない）

1. 既存の `アカウント設定_{アカウント名}.md`・`letter.md`（初代商品）＋`商品コンセプト台帳.md` を読む（演者の口調・キャラ・ターゲットは**既存のまま使う**。作り直さない）
2. ユーザーの一言コンセプト＋商品名から、**商品コンセプトブロック**（商品名／刺す問題点／約束する未来／アカ内構成での役割（メイン/サブ/ミニ）／価格）を作り、`アカウント設定_{アカウント名}.md` に「## 商品2：{商品名}」として**追記**（上書きしない）
3. **売れるかの検査だけは省略しない**：`スキル_恋愛コンセプト設計.md` Step 4 の**売れるコンセプト検査（5問・てっど理論接地）**＋`思考スキル_売上逆算.md`。通らないコンセプトはその場で代案を添えて報告
4. 価格・マガジンの位置づけは**コンセプト確定と同時に決める**（てっどの型：メイン2,980＋サブ1,980×1〜2＋ミニ980で月20-30万／新商品の初動は980円→口コミ→値上げ）。ユーザーの指示に価格が入ってたらそのまま採用。入ってなければC-0/C-1のコンセプト提示に価格案も含めて一緒に確定させる
5. 確定したら `商品コンセプト台帳.md` に1行追記

##### C-1.5：ここで人間タッチを全部済ませる（2026-07-06新設・重要）

コンセプト・価格が決まった時点で、**残りの人間作業を全部このタイミングに前倒しして潰す**。以降は公開まで一切止まらないため。

6. **サムネを先に作って選んでもらう**：サムネはメイン＝商品名なので、本編を書く前でも作れる。`Phase 7` のルールで**3案生成 → 人間が1枚選ぶ**。選んだ画像パスを覚えておき、Phase 8で自動セット（＝旧・公開直前のサムネ選びは廃止）
7. **noteログインを今のうちに通す**：`python x-to-threads/note_session.py --account {演者} --login` でセッション有効化。**reCAPTCHAが出るならここで1回だけ人間が通す**（毎回ここで潰しておけば、以降の下書き投入・公開でログインに引っかからない）
8. ここまでで**人間タッチは完了**。「じゃあ作るね」と言って Phase 2 へ入り、公開まで止まらない。**並列で複数商品を回す場合は、各タブ（各セッション）でこのC-1〜C-1.5の4点だけ人間が済ませてから走らせる**

#### C-2：Phase 2〜8＋公開 を商品別パスで実行（止まらない）

フローは通常のPhase 2〜8と同一（letter→content→図解→画像13枚→結合＋貼り付け→サムネ文字案→報告）。**違いはパスだけ**：

```
{アカウント名}/{商品スラッグ}/letter.md・content.md      ← 商品別フォルダ（初代商品の直下ファイルは触らない）
{アカウント名}_note_images/{商品スラッグ}_L_01〜C_10.png  ← 画像IDに商品スラッグを含める
note_tools/generate_{アカウント名}_{商品スラッグ}_images.py
note_tools/【note投稿用】{アカウント名}_{商品スラッグ}_完成版.md
note_tools/{アカウント名}_{商品スラッグ}_note自動貼り付け.py
```

- 商品スラッグ＝商品名から短い英数字（例：kidoku／fukuen2）。C-1で決めて全ファイルに使う
- **競合レター4本の構造分析（Step 2-0）は省略しない**（letterの質はここで決まる。既読ならその読みを使ってよいが未読で書き始めるのは禁止）
- letterの証拠・実績は初代letterと矛盾させない（同じ演者の別商品。数字・経歴の整合を保つ）
- マーカー導入文・画像枚数等は通常ルール通り

#### C-3：作り直し（リニューアル）の場合

- 既存の letter.md／content.md を読み、**何が弱かったか**を問題教育設計の観点で1〜3行診断（問題点が刺さってない／約束が抽象／競合と同じ 等）してから、新コンセプトでC-1→C-2を回す
- 旧商品ファイルは消さない（`{アカウント名}/{旧商品スラッグ}/` に残す。noteの旧記事も削除しない＝阪本方針）

#### 並列量産のやり方（複数タブ＝複数セッションで・2026-07-06明確化）

**並列は「タブ（セッション）を分けて、各タブ＝1商品」でやる。1つのセッション（1チャットのコンテキスト）で複数商品を同時に走らせるのは禁止**（コンテキストが混ざって工程飛ばし＝2026-07-05ゴム出力事故の原因）。サブエージェント並列も使わない（[[feedback_no_subagent]]・品質が落ちる）。

- **正しい並列**：人間がClaude Codeのタブを複数開き、各タブで別商品のC-1〜C-1.5（コンセプト/価格/サムネ選び/ログイン）を済ませて走らせる。各タブは自分の1商品だけを公開まで完走する
- 商品別パスなのでファイルは衝突しない（同一商品を2タブで回すのだけ禁止）
- **同一noteアカウントの下書き投入・公開（Phase 6/8）は同時に走らせない**（ブラウザセッション競合）。別演者アカなら完全並列OK。同一アカで複数商品なら、note操作の所だけ順番待ちになる
- 全タブが公開まで終わったら、1つのタブでマガジン化（Phase 11）へ

### Phase 2: letter作成

**参照**: `スキル_恋愛レター作成.md`

#### Step 2-0：競合レター4本の構造分析（必須・冒頭で実施）

## このスキルの本質

**「恋愛系演者運用の全工程を1スキルで統括する」**

カバー範囲：
- **note立ち上げ系**（Phase 1〜8）：コンセプト→letter→content→画像→note公開準備→サムネ文字案
- **Xポスト量産系**（Phase 9）：1日10本〜1ヶ月300本まで、セールスレターから売れる切り口を抽出して短文ポスト化

阪本さんが「あや立ち上げて」と言えば全工程ノンストップ、「うみこのポスト100本作って」と言えばPhase 9だけ起動。

新演者立ち上げ時も日次運用も、起動文1つに圧縮するのがこのスキルの目的。

### 既存スキルの圧縮はしていない

このスキル本体は**統括役（指揮者）**で、各フェーズで対応するスキル本体（スキル_恋愛コンセプト設計.md／スキル_恋愛レター作成.md／スキル_恋愛コンテンツ本編作成.md／**スキル_恋愛ポスト作成AI.md（v4）**／AIキット_各種.md）を**そのまま参照する**。中身を取り込んだり要約したりしていない。
